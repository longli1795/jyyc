# 电废经营预测系统 — 开发模式与生产模式说明

本文档说明本系统在 **开发模式** 与 **生产模式** 下的差异、启动方式及运维要点。

---

## 1. 模式切换原理

系统通过环境变量 `FLASK_ENV` 选择配置类（见 `app/config.py`）：

| `FLASK_ENV` 值     | 配置类                 | 用途      |
| ----------------- | ------------------- | ------- |
| `development`（默认） | `DevelopmentConfig` | 本地开发、调试 |
| `production`      | `ProductionConfig`  | 内网正式部署  |
| `testing`         | `TestingConfig`     | 自动化测试   |

> **注意：** 未设置 `FLASK_ENV` 时，等同于开发模式。

---

## 2. 开发模式 vs 生产模式对比

| 项目                        | 开发模式                                | 生产模式                                |
| ------------------------- | ----------------------------------- | ----------------------------------- |
| **DEBUG**                 | 开启                                  | 关闭                                  |
| **默认数据库**                 | SQLite                              | PostgreSQL（可通过环境变量改为 SQLite）        |
| **当前部署数据库**               | SQLite                              | SQLite（`DATABASE_TYPE=sqlite`）      |
| **Redis**                 | 推荐，不可用则回退文件会话                       | **必须**（启动脚本会预检）                     |
| **启动时清会话**                | 默认清空（`CLEAR_SESSIONS_ON_STARTUP=1`） | 不清空（`CLEAR_SESSIONS_ON_STARTUP=0`）  |
| **Session Cookie Secure** | 未强制                                 | 默认 `false`（HTTP 内网）；HTTPS 时设 `true` |
| **监听地址**                  | 默认 `0.0.0.0:8080`                   | `0.0.0.0:8080`（局域网可访问）              |
| **适用场景**                  | 单人本机调试                              | 内网多用户长期运行                           |

### Redis 不可用时的行为

两种模式在 Redis 连接失败时都会 **降级为文件会话**（`data_storage/sessions/`），但：

- **开发模式**：可临时无 Redis 运行，方便调试
- **生产模式**：强烈依赖 Redis，应确保 Redis 服务已启动

## 3. 开发模式

### 3.1 适用场景

- 修改代码、调试功能
- 本机单人使用
- 可接受每次重启清空会话数据

### 3.2 启动方式

**方式一：双击脚本（推荐）**

```
restart_app.bat
```

**方式二：命令行**

```bat
cd /d D:\电废经营预测系统\0525
python app.py
```

未设置环境变量时，`FLASK_ENV` 默认为 `development`。

### 3.3 开发模式特点

- `DEBUG=True`，错误信息更详细
- 每次启动默认 **清除所有用户会话数据**（等同首页「清除数据」）
- 可不启动 Redis（会自动降级）
- 仅本机访问时可用 `http://127.0.0.1:8080`

### 3.4 开发时可选环境变量

```bat
set FLASK_ENV=development
set FLASK_DEBUG=True
set CLEAR_SESSIONS_ON_STARTUP=1
set REDIS_URL=redis://localhost:6379/0
python app.py
```

若希望开发模式下重启 **不清会话**，可设：

```bat
set CLEAR_SESSIONS_ON_STARTUP=0
```

## 4. 生产模式

### 4.1 适用场景

- 内网正式环境、多人同时使用
- 需要局域网访问（`http://<服务器IP>:8080`）
- 长期运行、重启后保留用户数据

### 4.2 前置条件

1. **Redis** 已启动，默认地址 `localhost:6379`
2. **Python 依赖** 已安装（Flask、redis、sqlalchemy 等）
3. **防火墙** 已放行 8080 端口（局域网访问时需要）

### 4.3 启动方式

#### 方式一：前台手动启动（调试/临时）

```
start_production.bat
```

脚本会自动：

- 加载生产环境变量（`scripts/production_env.bat`）
- 检测 Redis 连通性
- 打印本机与局域网访问地址
- 启动应用

#### 方式二：守护进程 + 崩溃自动重启

```
scripts\run_production_service.bat
```

- 等待 Redis 就绪后启动
- 进程退出后 **10 秒自动重启**
- 日志写入 `logs/` 目录

#### 方式三：开机自启（推荐长期运行）

```
install_autostart.bat
```

- 优先创建 Windows 任务计划（需管理员权限）
- 若权限不足，自动改用「启动」文件夹快捷方式（登录后自启）
- 卸载自启：`uninstall_autostart.bat`
- 查看状态：`status_autostart.bat`

### 4.4 生产环境变量（`scripts/production_env.bat`）

| 变量                          | 生产值                        | 说明                 |
| --------------------------- | -------------------------- | ------------------ |
| `FLASK_ENV`                 | `production`               | 切换生产配置             |
| `FLASK_DEBUG`               | `False`                    | 关闭调试               |
| `FLASK_HOST`                | `0.0.0.0`                  | 监听所有网卡             |
| `FLASK_PORT`                | `8080`                     | 服务端口               |
| `PYTHONIOENCODING`          | `utf-8`                    | 避免控制台 emoji 乱码     |
| `SECRET_KEY`                | 强随机字符串                     | **务必修改默认值**        |
| `REDIS_URL`                 | `redis://localhost:6379/0` | Redis 连接           |
| `DATABASE_TYPE`             | `sqlite`                   | 当前使用 SQLite        |
| `SESSION_COOKIE_SECURE`     | `false`                    | HTTP 内网部署必须为 false |
| `CLEAR_SESSIONS_ON_STARTUP` | `0`                        | 重启不清会话             |

### 4.5 局域网访问

1. 确认服务监听 `0.0.0.0:8080`

2. 放行防火墙（管理员运行一次）：
   
   ```
   open_firewall_8080.bat
   ```

3. 其他设备浏览器访问：
   
   ```
   http://<服务器局域网IP>:8080
   ```
   
   例如：`http://10.30.5.32:8080`

### 4.6 健康检查

```
GET http://<服务器IP>:8080/api/system/health
```

正常响应示例：

```json
{
  "success": true,
  "status": "healthy",
  "database": "healthy",
  "redis": "healthy",
  "active_sessions": 21
}
```

## 6. 日常使用指南

### 6.1 平时用哪个脚本？

| 脚本 | 使用频率 | 用途 |
|------|----------|------|
| `install_autostart.bat` | **只装一次** | 配置登录后自动启动 + 崩溃自动重启 |
| `start_production.bat` | 按需使用 | 手动前台启动（调试、临时重启、看控制台） |
| `restart_app.bat` | 改 bug 时用 | 开发模式启动 |
| 无（自动运行） | **平时** | 安装自启后，登录 Windows 即自动在后台运行 |

**已安装自启后，平时不需要反复运行任何脚本。** 需要时可运行 `status_autostart.bat` 查看状态，或查看 `logs\service.log`。

> **注意：** 不要同时运行自启服务和 `start_production.bat`，会争抢 8080 端口。

### 6.2 修改 Bug 操作流程

```
1. 停掉生产服务（见第 7 节）
2. restart_app.bat          ← 开发模式调试
3. 改代码 → 保存 → Ctrl+C → 再启动验证
4. start_production.bat     ← 上线前用生产配置再测一遍
5. 恢复长期运行：
   - 注销/重启登录（自启自动拉起），或
   - 运行 scripts\run_production_service.bat
```

开发模式适合排查（`DEBUG=True`、报错更详细）；生产脚本用于确认 Redis、Session、局域网访问正常。

## 7. 进程管理与停服

生产环境运行时，实际涉及 **两个进程**：

```
cmd.exe  →  run_production_service.bat（守护循环）
              └── python.exe  →  app.py（Web 服务，占用 8080）
```

任务管理器中应搜索 **`python`** 查看 Web 服务，搜索 **`cmd`** 查看守护脚本（可能已最小化到任务栏）。

### 7.1 三种常见情况

#### 情况 A：关了所有 CMD 窗口，网站仍能访问

**正常。** 可能原因：

- 守护窗口被 **最小化** 到任务栏（标题类似 `BusinessForecastService`），并非真正关闭
- 或 `cmd.exe` 已结束，但 **`python.exe` 作为孤儿进程仍在运行**

此时服务可用，但若守护 `cmd` 已不存在，**崩溃后不会自动重启**。

#### 情况 B：结束 Python 后，很快又出现新的 Python

**正常。** 说明守护脚本 `run_production_service.bat` 仍在运行。结束 Python 约 10 秒后，守护会自动拉起新进程。

**正确停服顺序：**

1. 先结束命令行含 **`run_production_service.bat`** 的 `cmd.exe`
2. 再结束 **`python.exe`（app.py）**

只杀 Python 无法彻底停服。

#### 情况 C：任务管理器搜不到 cmd，但网站仍能访问

**正常。** 说明 **`python.exe` 还在跑**（守护 cmd 可能已被结束）。

| 项目 | 状态 |
|------|------|
| 网站访问 | 正常 |
| 崩溃自动重启 | **已失效**（守护 cmd 不在） |
| 彻底停服 | 在任务管理器结束 **`python.exe`** |

### 7.2 如何彻底停止服务

**方法一：任务管理器**

1. 搜索 **`cmd`** → 结束含 `run_production_service.bat` 的进程
2. 搜索 **`python`** → 结束 `app.py` 对应进程
3. 访问 `http://<IP>:8080` 应无法打开

**方法二：命令行**

```bat
status_autostart.bat
```

查看进程 PID 后，在任务管理器「详细信息」中结束对应进程。

### 7.3 停服后如何再启动

| 方式 | 操作 |
|------|------|
| 临时前台运行 | `start_production.bat` |
| 后台 + 崩溃自动重启 | `scripts\run_production_service.bat` |
| 已装自启 | 注销或重新登录 Windows |

### 7.4 进程状态对照表

| 现象 | 是否正常 | 说明 |
|------|----------|------|
| 关了可见 CMD，8080 仍能访问 | 正常 | Python 仍在运行 |
| 结束 Python 后又自动出现 | 正常 | 守护脚本在自动重启 |
| 搜不到 cmd，但仍能访问 | 正常 | 仅剩 Python 孤儿进程，无自动重启 |
| 结束 Python 后无法访问 | 预期 | 服务已停止 |

## 8. 日志与运维

### 8.1 生产服务日志

| 文件                        | 内容          |
| ------------------------- | ----------- |
| `logs/service.log`        | 守护进程启停、重启记录 |
| `logs/service_stdout.log` | 应用标准输出      |
| `logs/service_stderr.log` | 应用错误输出      |

### 8.2 定时维护

系统内置 **每小时** 清理过期会话（启动 5 分钟后首次执行），无需手动干预。

### 8.3 定时备份与恢复（长期运行必配）

生产环境长期运行时，**必须**配置定时全量备份。系统现有的「编辑前备份」「快照导入前备份」只能应对单次误操作，**无法**应对磁盘故障、误删目录、数据库文件损坏等灾难场景。

#### 8.3.1 必须备份的资产

| 优先级 | 路径 | 内容 |
|--------|------|------|
| 1 | `data_storage/business_forecast.db` | 用户账号、会话业务数据、计算历史 |
| 2 | `data/persistent/` | 期初库存（全系统唯一） |
| 3 | `data/base_data/` + 根目录 Excel | 映射、减扣、系数、费用、价格/补贴 |
| 4 | `data/snapshots/` | 用户主动保存的全量快照（建议每周备份） |

#### 8.3.2 一键安装定时任务

1. 编辑 `scripts/backup_env.bat`，将 `BACKUP_ROOT` 设为**另一磁盘或网络路径**（勿与项目同盘）：
   
   ```bat
   set BACKUP_ROOT=D:\BusinessForecastBackups
   ```

2. 以管理员身份运行（推荐）：
   
   ```
   install_backup_schedule.bat
   ```

安装后将创建三个 Windows 任务计划：

| 任务名 | 时间 | 内容 |
|--------|------|------|
| `BusinessForecastBackupDaily` | 每天 02:00 | DB 在线备份 + 核心数据目录/Excel |
| `BusinessForecastBackupWeekly` | 每周日 03:00 | 每日内容 + `data/snapshots/` |
| `BusinessForecastBackupCleanup` | 每月 1 日 04:00 | 清理 `snapshot_pre_load_*` 旧目录 |

查看状态：`status_backup_schedule.bat`  
卸载任务：`uninstall_backup_schedule.bat`  
备份日志：`logs/backup.log`

#### 8.3.3 手动执行

```bat
scripts\run_daily_backup.bat
scripts\run_weekly_backup.bat
scripts\run_cleanup_backups.bat
```

#### 8.3.4 保留策略（可在 backup_env.bat 调整）

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `BACKUP_DAILY_RETENTION_DAYS` | 14 | 每日备份保留天数 |
| `BACKUP_WEEKLY_RETENTION_WEEKS` | 8 | 每周备份保留份数 |
| `SNAPSHOT_PRELOAD_RETENTION` | 10 | 快照导入前临时备份保留份数 |

#### 8.3.5 恢复步骤

1. **停服**（见第 7 节）：先结束守护 `cmd`，再结束 `python.exe`
2. **恢复数据库**：从最新备份复制 `data_storage/business_forecast.db` 到项目 `data_storage/`
3. **恢复文件数据**：覆盖 `data/persistent/`、`data/base_data/`，并将备份中 `excel/` 下的 Excel 复制到项目根目录
4. **（可选）恢复用户快照**：从备份的 `data/snapshots/` 复制回项目
5. **启动服务**，访问 `/api/system/health` 确认 `database`、`redis` 均为 healthy
6. **（可选）业务会话恢复**：登录后在「数据管理」加载用户快照 ZIP

> 注意：恢复快照 ZIP 会覆盖会话与全局基础数据，但**不恢复用户账号**；完整灾难恢复需同时恢复 `business_forecast.db`。

#### 8.3.6 与现有机制的分工

| 场景 | 现有机制 | 定时备份 |
|------|----------|----------|
| 误改一条基础数据 | 编辑前备份 | 不必 |
| 误导入快照 | `snapshot_pre_load_*` | 不必 |
| 硬盘故障 / 误删 data 目录 | 不够 | **必须** |
| DB 文件损坏 | 不够 | **必须** |
| 服务器重装 Windows | 不够 | **必须** |

### 8.4 长期运行注意

- 使用自启/守护脚本时，关闭 **可见** CMD 窗口不一定等于停服（见第 7 节）
- 服务器重启后，若已安装自启，**登录后**会自动启动
- 守护脚本运行时，进程异常退出约 **10 秒**后自动重启
- 默认账号 `admin / admin123` 应在部署后修改密码

## 9. 常见问题

### Q1：生产模式启动报 Redis 连接失败？

确认 Redis 服务已启动：

```bat
python -c "import redis; redis.from_url('redis://localhost:6379/0').ping(); print('OK')"
```

### Q2：局域网其他电脑无法访问？

1. 确认服务监听 `0.0.0.0:8080`（非 `127.0.0.1`）
2. 以管理员运行 `open_firewall_8080.bat`
3. 确认客户端与服务器在同一网段

### Q3：生产模式登录后刷新又退出？

HTTP 内网部署须确保：

```bat
set SESSION_COOKIE_SECURE=false
```

`start_production.bat` 已默认设置。

### Q4：重启后用户数据被清空？

开发模式默认每次启动清会话。生产模式应使用 `start_production.bat` 或守护脚本，并确保：

```bat
set CLEAR_SESSIONS_ON_STARTUP=0
```

### Q5：`install_autostart.bat` 报「拒绝访问」？

创建任务计划需要管理员权限。脚本会自动改用「启动」文件夹快捷方式，**登录后同样能自启**，一般可正常使用。

### Q6：如何确认当前是哪种模式？

查看启动日志：

- 开发模式：`Debug mode: on` 或日志含「正在清除所有会话数据」
- 生产模式：`Debug mode: off` 且日志含「已跳过启动时清除会话数据」

也可访问 `/api/system/health` 确认 Redis、数据库状态。

### Q7：关了 CMD 窗口，局域网还能访问，正常吗？

**正常。** Web 服务由 `python.exe` 提供，不一定依赖可见的 CMD 窗口。详见 **第 7 节「进程管理与停服」**。

### Q8：任务管理器里结束 Python 后，很快又出现新的 Python？

说明守护脚本仍在运行，会自动重启。须先结束 `run_production_service.bat` 对应的 `cmd.exe`，再结束 Python。

### Q9：任务管理器搜不到 cmd，但网站仍能访问？

说明守护 cmd 已退出，**Python 孤儿进程**仍在服务。此时无崩溃自动重启；要停服请在任务管理器搜索 **`python`** 并结束进程。

## 10. 安全建议

1. **修改 `SECRET_KEY`**：编辑 `scripts/production_env.bat` 中的默认值
2. **修改默认管理员密码**：首次登录后立即修改
3. **仅内网使用**：当前使用 Flask 内置服务器，适合小团队内网，不建议直接暴露公网
4. **HTTPS 部署**：若后续启用 HTTPS 反向代理，设置 `SESSION_COOKIE_SECURE=true`

## 11. 架构示意

```
局域网客户端
    │
    ▼  http://<IP>:8080
Windows 防火墙 (TCP 8080)
    │
    ▼
Flask 应用 (app.py)
    ├── Redis (会话 / 缓存)
    └── SQLite (business_forecast.db)
```

**生产推荐启动链路：**

```
Windows 登录
    → 启动文件夹快捷方式 / 任务计划
    → run_production_service.bat（守护）
    → 等待 Redis → python app.py
    → 崩溃后 10s 自动重启
```
